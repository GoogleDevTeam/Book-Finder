# Pre-build test matrix

**Status:** Planned acceptance/verification cases only; not executed. The repository contains no application code. No result below implies a test passed.

## Execution rules

- Each case maps to a stable BF-REQ ID in APP_PLAN.md and states its input, expected result, pass criterion, owner/environment, and evidence.
- **Test owner:** not assigned; name an implementer/test runner before implementation approval. The project owner reviews acceptance evidence. **Device/Android versions:** TBD under Q-55/Q-58.
- Use synthetic or sanitized fixtures. Do not store real book titles, ISBNs, images, user identities, credentials, or signing keys in evidence.
- No OCR/match accuracy, latency, freshness, or revocation numbers are invented. Set those only after Q-17/Q-19/Q-31–Q-39/Q-64–Q-66/Q-70/Q-75 are resolved as applicable.
- Cases blocked by open owner choices are explicitly marked; research recommendations do not become approval. Live provider testing waits for a selected, permitted provider and eligible account.
- Capture app/build version, device/OS, fixture ID (not source content), timestamp, expected/actual result, and sanitized logs/screenshots. Record failures and retest evidence under the same TC ID.

After implementation is separately approved, execute applicable cases and retain evidence. No tests are currently run.
